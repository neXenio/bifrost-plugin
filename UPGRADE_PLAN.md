## Release checkpoint — 2026-11-11

Release [v1.10.3](https://github.com/neXenio/bifrost-plugin/releases/tag/v1.10.3) is published from `77ae1df19008aab89488975924b604ce2f590876` after release PR #22. Source changes in PRs #18–#21 are merged. The release commit and tag were cryptographically signed and verified.

Both local Claude Code plugin registrations (user and project) were upgraded to 1.10.3. All 19 checked tracked hook/manifest/package files matched the release. An isolated subprocess using the installed hook and live authenticated gateway emitted two recalled facts in 612 ms, with exit 0 and no stderr. This proves hook output, not consumption by an already-running Claude session; existing sessions require restart. Startup memory priming remains disabled by the effective signed policy.

The verification pass also passed 15 selected regressions and 12 executable-hook boundary checks. No full local suite ran. No CI existed at release time. The prior source-scoped 304-test result is historical evidence for unchanged hooks, not a new release-wide run.

At that release checkpoint, remaining work started with U03 credential selection, U06 supported runtimes/CI and U13 contributor instructions, alongside bounded documentation and compatibility research. U05 requires a coordinated keyapp contract; no production service changes are authorized by this plugin backlog alone. Work is committed and pushed only on new task branches; never directly to master/main.

## Evidence and limits

- Local research: host `Mac`, arm64, baseline SHA above. Runtime/distribution report is in ignored `temp/upgrade-audit/runtime.md`.
- Remote protocol research: reported host `macrunner.local`, arm64, same baseline; Claude Code 2.1.322 and strict manifest validation succeeded. This is protocol-seat evidence, not a local reproduction.
- Remote hooks/security audit: reported host `macrunner.local`, arm64, same baseline. Signature bypass and cross-identity cache findings were reproduced in memory; report path on that host: `temp/upgrade-audit/hooks.md`. No production attack, credential rotation or fleet security acceptance was performed.
- `macrunner-51` is not available as a paired Orca runtime. A remote Codex worker also failed before research because its installed client rejected the configured `gpt-6.1-sol` model. Native research fallback does not constitute x86_64 verification or repair those prerequisites.
- No full local suite, production mutation, npm publication, deployment, or fleet rollout is implied by this document. Completion requires the stated tests and actual CI evidence; a plan or metadata change is not runtime proof.
